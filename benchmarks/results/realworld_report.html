Conclusions

✅ Token Efficiency Claim: VALIDATED (87.6% avg, exceeds 60% claim)

FastContext delivers massive token savings for the solver model. The "explore → cite → solve" pattern consistently reduces context window consumption by 68-99%, freeing budget for actual reasoning.

⚠️ Retrieval Quality: MIXED (33% ground truth recall)

When FastContext finds the right files (q1, q4), answer quality matches full-repo context at a fraction of the cost. When it misses files (q2, q3, q5), the solver gets degraded context. The primary failure mode is search strategy — the model sometimes uses patterns that don't match the repo's naming conventions, or misses hidden directories.

Mitigation: Increase max turns from 6→8, or use broader initial Glob patterns.

✅ NVFP4 Viability: CONFIRMED

The NVFP4 model (2.7 GB, 11W) performs identically to BF16 for exploration tasks — tool calling, multi-turn reasoning, and citation generation all work correctly. This makes on-device, always-on code exploration practical on edge hardware.
